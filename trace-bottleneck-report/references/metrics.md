# 指标口径

所有时间:trace 的 `ts`/`dur` 为 µs,脚本内部用 µs,报告用 ms。每个数字都要能回答"母体、分母、单位、窗口"。

## 窗口与母体

| 概念 | 定义 |
| --- | --- |
| step 窗口 | 每个 rank 取一个**中间** `ProfilerStep#N`(完整 step 编号列表的中间一个;只有一个就用它;`--step` 可指定)。取 CPU 侧 `user_annotation` 事件,GPU 注解副本忽略。设备事件按窗口裁剪 |
| 设备事件 | `cat` 为 `kernel`、`gpu_memcpy`、`gpu_memset` |
| GPU 忙时 | 设备事件区间在**所有 stream 上的并集**。空闲 = step 窗口 − 忙时 |
| 累计耗时 | 各设备事件(裁剪后)耗时直接相加;多 stream 重叠时大于忙时 |
| 计算类 | 除 NCCL 通信和 memcpy/memset 搬运之外的所有 kernel,**含未分类** |

## 百分比分母

每个百分比列的表头都写明分母;表尾固定提示"累计类百分比因多 stream 重叠可能与占 step 不同,不可跨列相加"。保留 1 位小数,不足 0.1% 显示 `<0.1%`。

| 分母 | 含义 | 用于 |
| --- | --- | --- |
| 占 step% | 区间并集 ÷ 该 rank 的 step 窗口 | 总览、T1~T5、排行 |
| 占忙时% | 该类并集 ÷ GPU 忙时 | T1 |
| 占累计% | 该类耗时 ÷ 全部设备事件累计耗时,合计 100% | T1 |
| 占计算% | 计算类行:该类 ÷ 计算类合计;通信/搬运行留空 | T1 |
| 占空闲% | 该类间隙 ÷ 空闲总和 | T2 |
| 空闲/CPU% | 调用期间 GPU 空闲 ÷ 该调用 CPU 耗时(可超过 100%) | T3 |
| 重叠率% / 暴露占通信% | 与计算重叠(或暴露)的通信时长 ÷ 该集合通信区间并集 | T5 |

**不给百分比**:带宽占硬件峰值(trace 里没有峰值,仅当传入 `--peak-h2d-gbs`/`--peak-comm-gbs` 才显示)、起始极差、平均 kernel 时长、同步事件数、编译日志计数。

## T1 GPU 耗时速览

kernel 按名称正则分类(内置 CUDA+HIP 规则,`--rules` 可补充,补充规则优先);memcpy/memset 归"搬运"。未分类单列并在占累计 >5% 时提示补规则。top-3 kernel 按类别累计耗时排序。

## T2 空闲归因

对 step 内每个 GPU 空闲间隙只归一类,按此优先级:

1. **头部**:step 起点到首个设备事件;**尾部**:最后一个设备事件到 step 终点。头部另给"其中与搬运重叠"子行。
2. **搬运等待**:间隙与大拷贝(≥`--big-copy-mib`)的搬运窗口相关。窗口 = 该拷贝所在外层 `aten::to` 起点(找不到则 hip 调用起点)到设备拷贝结束。
3. **同步等待**:间隙与同步调用区间相关(设备/流/事件同步、`aten::item`、`aten::is_nonzero`、`aten::nonzero`、`aten::masked_select`;事件名可在规则文件中改)。
4. **通信等待**:间隙与 CPU 侧 `nccl:*` 标注区间相关。依据是 CPU 标注,属 `[推断]`。
5. **launch 小间隙**:其余间隙中长度 < `--small-gap-us` 的。
6. **未归因**:其余。

"相关" = 间隙起点落在窗口内,或间隙与窗口重叠 ≥50%。各类之和等于空闲总和。

## T3 同步表

- 嵌套事件只计最外层(`aten::is_nonzero` 内的 `aten::item` 不重复计)。
- **调用点**:有 Python 栈(`python_function` 事件或 `args["Call stack"]`)时取最内层项目帧 `file:line (func)`;trace 里的路径常是相对 `sys.path` 的,无法靠路径区分库与项目,所以按库前缀过滤,或用 `--project-hint` 指定项目片段。无栈时取外层 CPU 算子链(≤3 层,内层在前)并标"未定位到代码行"。`args["Call stack"]` 按"最内层在前"尽力解析。
- **调用期间 GPU 空闲** = 调用区间内的 GPU 空闲 + 返回后到下一个设备事件之间的残余间隙(残余只记到最后一个在该间隙内结束的调用)。
- **判定**(按顺序):设备/流/事件同步且调用期间 GPU 忙 ≥90% → "在等真实工作(不可消除)";调用点 GPU 空闲占 step <`--min-impact-pct` → "影响小"(CPU 耗时很短的调用,空闲/CPU 比例会很大但绝对影响可忽略);空闲/CPU ≥`--starve-pct` → "GPU 饥饿(值得改)";≤`--mask-pct` → "被掩盖";其间 "待观察"。

## T4 搬运表

- 只列 H2D/D2H ≥`--big-copy-mib` 的拷贝;DtoD 为设备内拷贝,汇总在小拷贝表并注明"不计入搬运"。
- **带宽** = 字节 ÷ GPU 侧 `Memcpy` 事件耗时,不含它之前的 CPU 转换。
- **拷贝前 GPU 空档**:紧邻该拷贝开始前的设备空闲。**前置 CPU copy_**:同一外层 `aten::to` 内、早于 hip 调用结束、且期间没有 hip/cuda 运行时调用的最长嵌套 `aten::copy_`。
- **提示**(均 `[推断]`):前置 CPU copy_ ≥1 ms → 疑似 CPU 侧 dtype 转换;带宽低于同类最大值一半 → 疑似 pageable 内存。

## T5 通信表

- 通信 kernel 由类别规则(`nccl*`/`rccl*`)识别,集合类型取 kernel 名中的 `Kernel_<Type>_`。
- **暴露** = 通信区间并集中未被非通信 kernel 覆盖的部分;**重叠** = 并集 − 暴露。
- **起始极差** = 各 rank 窗口内第 k 次同类集合的起始时间最大差,取中位和最大;各 rank 次数不一致则跳过。需要各 rank 时钟可比:脚本检查各 rank step 起点差 <50 ms,否则标"不可比"。多机数据默认不可比。
- **平均字节** 优先取通信 kernel 事件 `args` 里的 `In msg nelems × dtype`(新版 PyTorch 带有),没有则取 CPU 侧 `nccl:*` 标注的同名字段,都缺失则为 "—";算法带宽 = 平均字节 ÷ 平均 kernel 耗时,未含 NCCL 总线系数。

## 排行

候选与上限(均取自对应表,detail rank 的所选 step):

| 候选 | 上限 | 方向类别 |
| --- | --- | --- |
| 头部搬运空档 | T2 头部 + 搬运等待 | 数据搬运 |
| 同步导致 GPU 饥饿 | T3 判定"GPU 饥饿"的调用期间 GPU 空闲之和 | 同步消除 |
| 暴露通信 | T5 暴露 ms | 通信重叠 |
| launch 小间隙 | T2 launch 小间隙(`[上限]`,融合后不可能全回收) | launch 开销/融合/编译 |
| 慢 rank 等待 | 最慢 rank 空闲 − 各 rank 空闲中位数 | 慢 rank 排查 |

"未归因"不入排行。最大计算类别在排行下方单列"计算热点",不估上限。各上限可能重叠同一段空闲,不能相加。

## 旁证

- **运行记录**:`step_metrics` 的 `step_seconds` 给"第 11 步起中位数"和"末 3 步均值",与 trace 窗口不保证逐步对齐。
- **编译日志**:按关键字统计 "graph break"、"recompil" 及 guard 失败原因,格式随版本变化,属 `[推断]`。
- **key_averages**:按表头找 `Self CUDA` 列,取 top5。
- **HTA**:只读 CSV 摘要;其窗口与过滤规则与本报告不同。

## 默认阈值

`--small-gap-us 50`、`--big-copy-mib 1`、`--big-gap-ms 5`、`--slow-rank-ms 10`、`--starve-pct 50`、`--mask-pct 20`、`--min-impact-pct 0.5`、未分类提示 5%、同步"在等真实工作" 90%。是初始值,用目标项目的 trace 校准后再固定。
