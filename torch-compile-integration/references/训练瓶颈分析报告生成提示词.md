# 训练瓶颈分析报告生成提示词

使用 `torch-compile-integration` Skill 对当前 PyTorch 训练项目开展瓶颈诊断，结合 Profiler Trace、HTA 和实际源码，生成一份证据可追溯的瓶颈分析与 `torch.compile` 建议报告。表格呈现事实和对比，短段落解释推理。

使用 `grill-me` 与我确认影响分析有效性、且无法从现有材料核实的问题，不设固定询问轮数。普通分析选择自行判断并记录必要假设。

本轮仅分析：允许读取源码和已有数据、运行离线分析及生成报告；不启动训练或推理，不执行项目入口，不修改项目源码，不安装或升级运行依赖。需要补采或实验时只提供方案，等待确认。

## 输入

- 项目路径：【路径】
- 训练命令或配置：【未知则从项目中查找】
- 采集时训练 Python 环境：【从采集记录核实；无法确认则标记未知】
- 采集时硬件与后端：【设备型号、CUDA / HIP / DTK 等；从采集记录核实，无法确认则标记未知】
- 优化目标：【吞吐、总训练耗时、峰值显存或首步延迟，注明优先级；可选填写预计训练步数与编译缓存复用方式】
- Profiler Trace：【同一次运行的 Trace 文件或各 rank 目录】
- 分析环境：【离线分析的 Python 环境；HTA 若使用独立环境请注明，未知则检查当前环境】
- 显存快照、图断日志或 tlparse 报告（可选）：【路径】
- 优化前后两组数据（可选）：【路径及对应配置】
- 输出目录：【路径；未指定时创建独立的带时间戳目录】

默认交付 Markdown 报告和必要复算材料；CSV 仅保存支撑关键结论的表，图表按需生成。原始 Trace 保持只读。

## 分析流程

1. **核实环境与数据。** 读取项目 `AGENTS.md`、训练入口、有效配置和日志，核实实际模型结构、训练调用链及已有编译范围；分别记录采集环境与分析环境，采集环境未知时不得用当前环境代替。检查代码版本、Trace 来源、rank、有效 step 和设备事件；只有一个有效 active step 时标明“单步样本”，不据此认定稳态或代表性。
2. **使用 `profile-model` 概览瓶颈。** 检查 CPU/GPU 算子、kernel、设备活动空档、搬运、同步、通信和 rank 差异，再选择代表性 rank、慢 rank 及训练阶段深入分析，说明选择依据。
3. **使用 HTA 汇总与交叉检查。** HTA 可用且 Trace 兼容时，先验证导入与单 rank 解析，再分析 temporal breakdown、GPU kernel breakdown 和 idle-time breakdown；多卡任务增加通信计算重叠与 rank 差异分析。优先复用来源和统计范围仍有效的解析结果，避免重复分析。HTA 不可用、Trace 不兼容或部分 API 失败时，逐项记录状态、警告和证据缺口，保留成功结果，继续原始 Trace 与源码分析，不为此自动安装依赖，也不将其他工具结果称为 HTA 结果。HTA 与原始 Trace 来自同一批数据，不构成独立实验验证；关键结论回到原始时间线抽查。CSV 仅保存支撑结论的表，图表按需生成。若有优化前后两组数据，先核对配置和口径再比较。
4. **按输入开展专项分析。** 有显存快照时，使用 `analyze-memory-snapshot` 分析分配、生命周期和碎片等问题；有图断／重编译日志或 tlparse 报告时，先按 Skill 的 P4 判断原因、实际影响和处理方向，重编译关联 P3，重复层／嵌套编译关联 P7，再按需使用 `debug-graph-breaks` 深入定位。本轮仅输出边界调整、保持语义的 Tensor 改写或局部 eager 建议及验证计划，不直接修复；低影响或修改成本偏高的项记录后暂缓，阻止目标捕获或影响正确性的问题单独处理。缺少对应数据时，明确标记专项分析未完成；可结合源码及已有日志提出假设，但不得将其表述为已验证结论。需要补采时本轮只提供方案，后续经用户明确授权再开展采集任务。
5. **结合源码评估 Compile 候选。** 按热点和真实调用链比较整模型、训练步骤、子模块及局部 Tensor 计算边界。列出源码位置、实例范围、热点证据、接入位置、初始配置、风险与验证方法。分类为 A 直接试编译、B 当前保持 eager、C 小范围重构后试编译、D 证据不足。只有证据充分时推荐首选方案；证据不足或主要瓶颈来自数据加载、通信等非编译因素时，可建议“暂缓 Compile”，说明缺少什么证据，不强行输出 A/C 类候选。实验优先级不代表已证实的收益排名。
6. **给出建议与后续清单。** 结合优化目标和成本说明是否值得进入编译实验。适合继续时给出首选与必要替代方案的接入和验证计划；暂缓时列出需要补充的证据。其他瓶颈单独列入后续事项。

## 后续接入与验证计划（本轮仅提出）

- **接入与回退：** 优先复用现有配置或环境变量，在初始化入口集中控制，支持全部关闭、单项启用及必要的组合消融，减少模型源码改动。明确关闭时回到原始 eager 还是重构后 eager，保留已有编译状态的记录；切换方案使用独立进程，避免重复或重叠包装。
- **正确性与消融：** 设计同输入、同精度、同训练与分布式配置的 eager/compile 对照，覆盖输出、loss、梯度、参数更新、数值有限性及保存重载。存在计算重构时，区分原实现、重构后 eager 和重构后 compile；单项确认后再安排必要的组合对照。
- **Trace 与测速：** 计划采集接入前后同设置、同阶段的代表性 Trace，检查实际捕获、输入形状/长度/padding 变化、重编译次数与触发步号、guard 原因、重编译上限和预热充分性。正式测速独立进行，关闭 Profiler、诊断日志与额外数值检查，充分预热并重复测量迭代耗时、吞吐量和峰值显存，单独记录首次调用成本及缓存状态。缺少日志时注明证据缺口；分别判断编译是否生效、正确性是否通过、性能是否改善。

## 条件量化

- **覆盖比例与理想上界：** 能归属候选的可分离关键路径墙钟占比为 `p` 时，在其余耗时不变、该部分趋近零的假设下，最大耗时下降比例为 `p`，阿姆达尔理想加速上界为 `1 / (1 - p)`。写明假设；不能将 kernel 累计占比或 Python 窗口差值直接代入，也不能叠加重叠候选的上界。
- **回本步数：** 有可比的有效冷启动和稳态对照时，用 `ceil(C / Δt)` 估算；`C` 为相比基线新增的一次性成本（无新增成本时取 0），`Δt` 为同口径稳态平均步耗时的节省。注明冷/热缓存及后续重编译的影响；首步耗时差仅作为成本代理时标为粗估。缺少数据或未达稳态时填“无法估算”，`Δt <= 0` 时标为无稳态收益，不计算有限回本步数。

## 操作约束与资源保护

- 离线分析保持项目源码和原始数据只读，仅在独立输出目录生成必要产物，不覆盖历史结果。
- 补采或实验方案包含目的、命令、卡数、batch、步数、采样设置、时间预算、资源检查和停止条件，优先使用已有采集入口或不改源码的外部包装。本轮不执行，确认后再开展对应任务。
- 按可用资源分级解析：全体文件元数据检查 → 单 rank 试解析 → 分批扩展。避免默认并行加载全部 rank，记录实际覆盖范围、耗时和可取得的内存指标；资源不足或失败时按原因降级，不重复执行相同的 OOM 解析。单 rank 试解析不代表完成多卡分析。默认不建立 Parquet 缓存。
- Skill 按名称识别，调用形式适配当前客户端；先核实是否安装且可使用。缺少协作 Skill 时按 `torch-compile-integration` 的规则按需获取、校验和读取，无法获取时使用包内流程并注明限制。方法遵循相关 Skill，执行范围以本任务和用户授权为准。

## 统计口径与结论

- 明确时间窗口、单位和百分比分母，区分主机墙钟、kernel 累计时长和包含 kernel、memcpy、memset 的设备活动并集。有可靠的阶段标注或关联信息时才分阶段归属；缺失时标为推测或未归类，不按 CPU 时间区间硬切 GPU 事件并当作模块耗时。
- 原始事件空档与 HTA idle 分列，`non_compute_time` 不称为 idle，kernel 时间占比不称为硬件利用率。HTA 各项失败和警告分别记录，不以其他分析冒充 HTA 结果。
- 结论行内按需组合 `[实测]`、`[源码]`、`[推断]`、`[待验证]` 标签。小 kernel 多、同步阻塞或窗口差值仅作为线索。编译包装或图捕获成功不等于目标后端数值正确性通过，未做适用数值验证时明确标注。
- Profiler/HTA 用于诊断，正式测速另行设计。预热充分性须结合形状覆盖、重编译及测量窗口稳定性判断，不能仅凭完成固定预热步数认定稳态。

## 报告结构与交付

生成中文报告 `<项目名>_training_trace_compile_analysis.md`，按“总览 → 逐项证据 → Compile 建议 → 验证与后续工作”组织，保留以下 0–7 章。摘要聚焦 3–5 条主要发现；正文围绕关键瓶颈展开，支撑关键结论的明细按需放 CSV 或附录，不设固定页数，不为每章强制增加表格。

| 章节 | 内容与组织方式 |
| --- | --- |
| 0. 摘要 | 概括主要发现、量化依据和首选方案或暂缓结论，标明推断与限制。 |
| 1. 环境、配置与数据口径 | 分列采集环境与分析环境，记录优化目标、实际训练配置、可训练部分、Trace 和分析范围；另列实际模型部件、数量及依据，说明时间口径、HTA 口径与采集限制。 |
| 2. 主要瓶颈及证据 | 先给“类别、对应小节、量化证据、候选方向”总表；2.1 在关联证据充分时分解代表性 step，否则保留可确认的统计与未归类区间；后续按证据分析通信、主机等待、搬运、计算热点、已有编译及数据加载。 |
| 3. 建议编译的位置 | 候选表记录实验顺序、源码符号与实例范围、分类、依据、边界/接入位置和风险，增加“覆盖比例/理想上界”“回本步数”两列，按条件量化；说明候选包含或互斥关系及已有包装。 |
| 4. 推荐范围、初始配置与验证 | 按接入与验证要求说明配置、回退、单项/组合消融、前后 Trace 和独立测速；区分编译生效、正确性与性能结论。暂缓时说明需要补充的证据和后续验证条件。 |
| 5. 当前不优先通过 Compile 处理的路径 | 汇总其他瓶颈的位置、证据引用、当前判断、后续方向和风险，引用第 2 章而不重复论证，不作永久不可编译的判断。 |
| 6. 证据等级与未验证项 | 汇总重要证据缺口、矛盾和未验证项，说明它们如何限制结论；不重复抄录前文已经带标签的事实。 |
| 7. 后续建议（本次不执行） | 按依赖关系和优先级列出补采、Compile 对照及其他专项任务，说明目的、输入和完成标准；附产物索引与复算命令。 |

第 2 章仅在阶段归属证据充分时给出阶段、时间范围、窗口时长、计算与通信、kernel 数及候选判断，并保留未归类区间；后续小节按“量化观察 → 源码调用链 → 可能机制 → 结论与限制”展开。模块划分和小节数量随项目调整，不照搬其他模型。

默认交付 Markdown 和必要复算材料，包括输入索引、分析参数及实际使用的复算脚本；CSV 仅保留支撑关键结论的表，图表与详细日志按需提供，避免重复附件。复算脚本支持重新指定输入与输出。交付前核对表格计算、单位、分母、源码引用及前后结论。没有实际编译对照时，明确标注：**编译建议尚未验证收益**。
